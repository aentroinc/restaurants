# 8-week PoC Operating Playbook
# 外食チェーン経営OS 8週間PoC運用台本 v1

## 0. この資料の目的

本資料は、外食チェーン経営OSの有料PoCを8週間で成功させるための運用台本である。

プロダクトを作るだけではPoCは成功しない。PoCでは、顧客の経営陣、経営企画、店舗運営、SV、商品部、情シス、経理を巻き込み、以下を明確にする必要がある。

1. 何の経営課題を検証するのか
2. どのデータを使うのか
3. どのKPIを正とするのか
4. どの店舗に改善余地があるのか
5. どの会議体で使うのか
6. 本導入に進む判断基準は何か

---

# 1. PoCの基本設計

## 1.1 PoCの目的

PoCの目的は、単にダッシュボードを作ることではない。

目的は以下。

> 顧客の既存データを使い、店舗別の利益改善余地、悪化要因、SVが見るべき店舗、経営会議で議論すべき論点を可視化し、本導入のROIを判断できる状態にすること。

## 1.2 PoCの推奨スコープ

| 項目 | 推奨 |
|---|---:|
| 期間 | 8週間 |
| 対象ブランド | 1〜2ブランド |
| 対象店舗 | 20〜50店舗 |
| 対象データ期間 | 13〜25か月 |
| 主要データ | POS、勤怠、店舗別PL、商品マスタ、店舗マスタ |
| 追加データ | 原価、仕入、廃棄、販促、レビュー、SV巡回 |
| 成果物 | 経営会議レポート、店舗改善ランキング、ROI試算、本導入提案 |

## 1.3 PoC成功条件

以下のうち3つ以上を満たせば成功とする。

| 成功条件 | 判定基準 |
|---|---|
| 経営陣が見るべき店舗を特定できた | 利益悪化/改善余地上位店舗が合意される |
| 主要な悪化要因を説明できた | 人件費、原価、客数、商品構成などに分解できる |
| SVの巡回優先順位に使える | 店舗運営本部/SVが納得する |
| 経営会議資料として使える | 経営会議または役員報告で利用される |
| ROI仮説が出た | 年間改善余地がPoC費用/本導入費用を上回る |
| 本導入範囲が明確になった | 対象店舗、モジュール、連携データが決まる |

# 3. 8週間スケジュール

## Week 0：契約前準備

### 目的

PoC契約前に、スコープ、価格、データ、体制、成果物を合意する。

### 実施内容

- PoC提案書提示
- 対象ブランド/店舗の仮決定
- 必須データの有無確認
- NDA締結
- セキュリティ説明
- PoC費用/期間/成果物合意
- キックオフ日程調整

### 成果物

- PoC提案書
- NDA
- データ依頼書
- セキュリティ説明書
- PoCスコープ合意書

### Go/No-Go条件

- Executive Sponsorがいる
- データ提供責任者がいる

- PoC費用が合意されている

## Week 1：Kickoff & KPI Definition

### 目的

PoCの目的、対象範囲、データ、KPI定義、成功条件を明確にする。

### 会議

1. キックオフ 90分
2. KPI定義ワークショップ 90分
3. データ受領確認 60分

### アジェンダ：キックオフ

1. PoC目的確認
2. 対象ブランド/店舗確認
3. 参加者/役割確認
4. スケジュール確認
5. データ依頼内容確認
6. 成果物確認
7. 成功条件確認
8. リスク確認

### KPI定義で決めること

| KPI | 決める内容 |
|---|---|
| 売上 | 税込/税抜、値引き前/後 |
| 客数 | 会計客数/注文数/来店組数 |
| 客単価 | 売上 ÷ 客数 の定義 |
| 原価 | 理論原価/実績原価/仕入原価 |
| 人件費 | 社員/アルバイト/派遣/社会保険の扱い |
| 人時売上 | 売上 ÷ 労働時間 |
| 店舗営業利益 | どの費用まで含めるか |
| FL比率 | Food + Labor の範囲 |
| 改善余地 | 類似店舗中央値との差分を使うか |

### 成果物

- PoC Charter
- KPI Definition Sheet
- Data Request Confirmation
- Meeting Notes

### Week 1完了条件

- 対象店舗が確定している
- データ提出期限が確定している
- KPI定義の暫定版が合意されている

## Week 3：Data Quality & Reconciliation

### 目的

データ品質を確認し、元データと取り込み後の数値が一致するか検算する。

### 実施内容

- Canonical Modelへの変換
- データ品質チェック
- POS売上合計とPL売上突合
- 商品別売上合計と日次売上突合
- 人件費合計の突合
- 原価率/人件費率の異常値確認
- 顧客への確認事項整理

### Reconciliation項目

| 項目 | 許容差分 |
|---|---:|
| POS日次売上合計 vs 顧客売上報告 | ±0.5% |
| 商品別売上合計 vs 店舗日次売上 | ±1.0% |
| PL売上 vs POS月次売上 | ±1.0% または差異理由説明 |
| 勤怠人件費 vs PL人件費 | ±3.0% または差異理由説明 |
| 原価 vs PL原価 | ±3.0% または差異理由説明 |

### 成果物

- Reconciliation Report
- Data Quality Issue List
- KPI Calculation Confirmation
- Data Go/No-Go Decision

### Week 3完了条件

- 分析に使えるデータが確定している
- KPI計算に重大な不整合がない
- 顧客が主要数値を確認している

### 目的

### 実施内容

- 店舗別原因分析
- 類似店舗比較
- 人時売上分析
- 原価率分析
- 商品構成分析
- 売上/客数トレンド分析
- SV/店舗運営ヒアリング

### 深掘り対象

- 利益悪化上位10店舗
- 改善余地上位10店舗
- 人件費異常上位5店舗
- 原価異常上位5店舗
- 現場が気になる店舗5店舗

### 成果物

- Store Profit Diagnosis Report
- Root Cause List

### Week 5完了条件

- 主要な悪化要因が分類されている
- 顧客の店舗運営部門が納得する原因仮説が出ている

# 6. PoC中のリスクと対策

## 6.1 データが汚い

### 症状

- 店舗コード不一致
- 商品コード不一致
- POSとPLが合わない
- 原価データがない

### 対策

- Week 2〜3でData Quality Reportを必ず出す
- 使えるデータ/使えないデータを分ける
- まずは売上/人件費/PLで分析を成立させる
- 原価がなければPL原価から開始する

## 6.2 経営陣が見ない

### 症状

- 担当者レベルで終わる
- PoC成果が役員に届かない

### 対策

- Week 0でExecutive Sponsorを必須にする
- Week 4時点で中間報告を入れる
- Week 8のExecutive Readoutを契約時点で予定する

## 6.3 現場が納得しない

### 症状

- ランキングが現場感と違う
- SVが使えないと言う

### 対策

- 類似店舗比較を入れる
- SVヒアリングをWeek 5〜6で実施
- 現場が見るべき店舗を手動で追加し、モデルと比較する

## 6.4 改善余地が大きく見えすぎる

### 症状

- 経営陣から「本当か？」と言われる

### 対策

- Conservative / Base / Aggressive の3段階で出す
- 推定と実績を明確に分ける
- 類似店舗中央値ベースで保守的に試算する

## 6.5 情シス/法務で止まる

### 対策

- 契約前にSecurity Briefを出す
- 個人情報は原則不要とする
- データ削除/保管/アクセス権限を明記する
- AI学習利用しないことを明記する

# 7. 本導入判断基準

PoC後、本導入に進む判断基準。

## 7.1 Business Criteria

- 年間改善余地が本導入初年度費用の2倍以上
- 経営会議/店舗運営会議で使える見込みがある
- 店舗運営本部がSV Missionに価値を認める
- 対象データが全社展開可能

## 7.2 Technical Criteria

- 主要データ連携が可能
- 店舗/商品マスタ統合が可能
- KPI突合差異が許容範囲
- セキュリティ要件に大きなギャップがない

## 7.3 Organizational Criteria

- Executive Sponsorが継続する
- Business Ownerが明確
- Data Ownerが明確
- 本導入プロジェクト体制を組める

# 10. PoCを成功させる最重要原則

1. 最初から全部やらない
2. 経営陣に刺さる店舗改善余地から見せる
3. データ品質問題を隠さない
4. 改善余地は保守的に出す
5. 経営会議で使う形に落とす
6. SV/現場が納得する類似店舗比較を入れる
7. 本導入判断に必要なROIを必ず出す

PoCの最終ゴールは、きれいな画面を作ることではない。

> 顧客が「次は全社データでやりたい」と言う状態を作ること。
