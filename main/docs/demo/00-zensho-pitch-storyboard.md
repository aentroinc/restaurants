# Zensho 商談ストーリーボード (30分)

> 想定: ゼンショーホールディングス 経営企画 / 情報システム / すき家事業本部
> 利用画面: AENTRO Restaurant OS (`http://localhost:3000`, テナント: `demo`)
> データ前提: `make demo-up` 実行済み (80 店舗 / 90日 sales / Incident 8件 / HACCP / 200 employees)

---

## 進行サマリ

| 場面 | 時間 | 画面 (URL) | 主訴 |
|---|---|---|---|
| 1 | 0:00-4:00 | `/zensho-executive` | 全国一目俯瞰・要注意店舗ハイライト |
| 2 | 4:00-10:00 | `/incidents` → `/ai-analyst` → `/tasks` | 異常検知 → 根本原因 → 自動タスク発行 |
| 3 | 10:00-15:00 | `/labor` (シフト最適化) | 店長3h編成 → 15分 |
| 4 | 15:00-19:00 | `/sv-missions` (現場チェック モバイル想定) | 写真+geofence で品質担保 |
| 5 | 19:00-25:00 | `/incidents/[demo]` → `/meeting-packs` | 危機 → 役員レポ自動生成 |
| 6 | 25:00-30:00 | `/admin/roles` + `/admin/access-logs` | FC会計データの権限分離 |

> ※ 各場面は「3分話し / 1分操作」を目安。ガイドライン: PoC を 30 分で締める。

## 場面1: 経営ダッシュボード (4分)

**画面**: `/zensho-executive`

**遷移**:
1. ログイン → top redirect
2. すき家ブランド → 全国マップで赤ピン (要注意店舗) 強調
3. ブランド比較タブ: 売上 / 客数 / 人時生産性

**読み上げセリフ (要点)**:
- 「ゼンショー様は全国 1 万店舗超、5 ブランドの巨大グループ。本部経営層が **5 秒** で『今日危ない店』を把握できる画面が AENTRO の経営ダッシュボードです」
- 「すき家の異物混入のような問題は、**現場の小さなアラートが本部に届くまで** が遅れる。我々はこの遅延を **数秒** に縮めます」
- (赤ピンをクリック) 「この店、昨日から客数が標準偏差を 2.5 σ 下回っています。理由を AI に聞きましょう」

**スクショ差込**: `[SS-1-1: マップ全景]` `[SS-1-2: ブランド比較表]` `[SS-1-3: 赤ピン詳細]`

## 場面2: 異常検知 → AI根本原因分析 → タスク発行 (6分)

**画面**: `/incidents` → `/ai-analyst` → `/tasks`

**遷移**:
1. `/incidents` でデモ済み 8 件のうち「すき家 異物混入(髪の毛)」をクリック
2. 「AI に原因分析を依頼」ボタン
3. AI Analyst が hourly_sales / SV findings / レビュー / HACCP を横断クエリ
4. 結論: 「深夜帯ワンオペ + 衛生研修未受講者 2 名 / SNS 拡散経路 3 件」
5. 「タスク発行」→ `/tasks` で 5 件自動作成 (本部広報 / 店長 / SV / 法務 / 教育部)

**読み上げセリフ**:
- 「異物混入はゼンショー様にとって過去最大級のリスク。今回の発見は本部広報よりも先に **SNS** で起きました」
- 「我々の AI Analyst は **POS / SV報告書 / レビュー / HACCP** を横断的に見ます。RAG ではなく **構造化 + ベクトル混合** で、根拠ソースを必ず引用します」
- 「3 つのシナリオを提示します。**実行する前に CFO 承認** が必要なものは赤くマークされます。Foundry でいう 'Action with Approval' です」
- 「タスクは即時 5 件発行。役割別。期限・承認者・期待インパクトつき」

**スクショ差込**: `[SS-2-1: incidents 一覧]` `[SS-2-2: AI Analyst の根拠引用]` `[SS-2-3: tasks 自動生成]`

## 場面3: シフト最適化 (5分)

**画面**: `/labor`

**遷移**:
1. すき家 直営 渋谷店 を選択
2. 来週のシフト編成画面: AI 推奨ボタン
3. 制約 (法令・スキル・希望休) を反映した最適解を 8 秒で提示
4. 店長が 1 名スワップ → リアルタイム再計算

**読み上げセリフ**:
- 「シフト編成、店長は週 3 時間使っています。年 156 時間 × 1 万店舗 = **156 万時間**。これを 15 分にします」
- 「労基法・36 協定・最低賃金・**外国人技能実習生のビザ条件** まで全部制約に入れます。違反するシフトは出ません」
- 「ココスのピーク人員不足、なか卯の券売機トラブル、すき家の深夜ワンオペ、**全部このエンジンで一掃** できます」

**スクショ差込**: `[SS-3-1: シフト編成 Before/After]` `[SS-3-2: 制約一覧]` `[SS-3-3: 法令違反警告]`

## 場面4: 現場チェック (4分)

**画面**: `/sv-missions` (モバイル幅 375px で表示)

**遷移**:
1. SV (スーパーバイザ) の今週ミッション一覧
2. 店舗到着 → geofence で自動チェックイン
3. QSC チェックリスト: 各項目に写真添付必須
4. 「冷蔵庫温度 OK」を撮影 → HACCP 記録に自動連携
5. 異常があれば即 incident 起票

- 「写真は **改ざん不可・タイムスタンプ付き**。これが **HACCP 監査** の証跡になります」
- 「すき家の冷蔵庫温度逸脱、ココスの清掃不備、リアルタイムで本部が見えます」

**スクショ差込**: `[SS-4-1: モバイル版ミッション一覧]` `[SS-4-2: 写真+geofence]` `[SS-4-3: HACCP 連動]`

## 場面5: 危機対応 (6分)

**画面**: `/incidents/[id]` → `/meeting-packs`

**遷移**:
1. インシデントから「役員レポ生成」ボタン
2. AI が以下を 90 秒で自動構成:
   - 1 ページ目: 何が起きた / 影響範囲 / 現状ステータス
   - 2 ページ目: 売上影響シミュレーション (店舗別 × 7日)
   - 3 ページ目: 対応シナリオ 3 案 (pros/cons/risk/confidence)
   - 4 ページ目: 想定 Q&A (記者会見対策)
3. PDF / Slack / メールに即配信

**読み上げセリフ**:
- 「すき家異物混入のとき、ゼンショー様は **記者会見まで 36 時間** だった。我々は **30 分** で会見資料の **下書き** ができます」
- 「ハルシネーション対策として、すべての数字に **ソースクエリ** が紐づいています。経営判断の証跡として残ります」

**スクショ差込**: `[SS-5-1: meeting-pack 表紙]` `[SS-5-2: 売上影響シミュ]` `[SS-5-3: シナリオ 3 案]`

## トラブル時の逃げ道

| 症状 | 対処 |
|---|---|
| マップが白い | `/zensho-executive` リロード、それでもダメなら `/incidents` から開始 |
| AI 応答が遅い | 「実環境では SLA 5 秒。今ローカルなのでデモ用キャッシュあり」と説明 |
| seed 失敗 | `make demo-reset` 後、もう一度 `make demo-seed` |
