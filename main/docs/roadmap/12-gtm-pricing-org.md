# 12 — GTM / 価格 / 組織（配点なし / 必要条件）

## 課題
製品が 100 点でも、売れなければ「業界デファクト候補」にならない。Palantir Foundry の凄みは技術 50% + Forward Deployed Engineer 中心の **販売・実装組織** が 50%。同じ構造を日本の外食バーティカル向けに作る必要がある。

## ゴール
1. **価格モデル**: 顧客規模 × プランで明確、年商 100 億〜数千億円顧客に違和感なく ¥30M-300M / 年で売れる
2. **GTM 戦略**: ICP 定義 / 競合差別化 / セールスプロセス / パートナーチャネル
3. **組織設計**: T+12M でコア 12 人 + 拡張時の hiring plan
4. **Customer Success 体制**: パイロット → 本契約 → 拡張の標準フロー
5. **業界 KOL 戦略**: 業界団体 / メディア / カンファレンス露出

## B. 価格モデル

### B.1 3 プラン構成

| プラン | 対象 | 構成 | 価格 |
|-------|------|------|------|
| **Standard** | 中小〜中堅 | shared DB / 共有環境 / 平日サポート | ¥1.2M-3.6M / 月 |
| **Pro** | 中堅〜大手 | isolated DB / shared VPC / 24x5 サポート | ¥3M-8M / 月 |
| **Enterprise** | 大手 / 上場 | dedicated VPC / 専任 CS / 24x7 / SLA 99.95% | ¥8M-25M / 月 |

### B.2 価格構成要素

```
基本料 (テナント / 月)
  + 店舗数チャージ (¥3,000 - ¥10,000 / 店舗 / 月)
  + データ容量チャージ (TB ベース、初期は無償枠 1TB)
  + LLM 利用料 (¥100K - ¥500K / 月、cap あり)
  + プロフェッショナルサービス (実装 + 業界深掘り、初年度 ¥10-30M)
```

### B.3 価格根拠（ROI ベース）

§00-overview の価値計算で：
- 50 店舗チェーン: 顧客側 ¥190M / 年の改善 → ARR ¥30M (15%)
- 500 店舗チェーン: 顧客側 ¥1.9B / 年の改善 → ARR ¥150M (8%)

**「投資対効果 5-15x」**を提案書の標準フレームに。

### B.4 契約形態

- 標準: **1 年間最低契約**（multi-year で 10-20% 割引）
- パイロット: 8 週間 ¥3-5M（成功時に本契約への credit）
- 解約: 90 日前通知、データ持ち出し（CSV/Parquet） 30 日間サポート

## G. Customer Success 設計

### G.1 ライフサイクル

```
[Pilot 8週] → [Onboarding 3ヶ月] → [Adoption 3ヶ月] → [Expansion 6ヶ月+] → [Renewal]
```

各フェーズで CSM 担当 + 標準成果物：

| フェーズ | 標準成果物 | 顧客指標 |
|---------|-----------|---------|
| Pilot | 8 週レポート / ROI 試算 | 経営承認 |
| Onboarding | 全店データ取込 / 経営会議で活用開始 | DAU / 主要 KPI 表示率 |
| Adoption | 5 ロール以上 が日次利用 | DAU/MAU > 50% |
| Expansion | 2 機能以上の追加導入 | 拡張 ARR / 紹介数 |
| Renewal | NPS > 50 / 解約懸念ゼロ | 継続率 95%+ |

### G.2 ヘルススコア

```python
def health_score(customer) -> Literal["green", "yellow", "red"]:
    signals = {
        "dau_ratio": customer.dau / customer.total_users,         # > 0.4 が good
        "key_kpi_views": customer.weekly_kpi_views_per_user,     # > 5
        "ai_usage": customer.ai_queries_per_user_week,           # > 3
        "ingestion_health": customer.last_30d_ingestion_success_rate,  # > 0.95
        "csm_touchpoints": customer.csm_meetings_last_30d,        # >= 1
        "support_tickets_severity": customer.high_severity_tickets_open,  # 0 が good
        "executive_sponsor_active": customer.exec_sponsor_login_last_30d,  # true
    }
    return aggregate(signals)
```

red 1 週間 → CSM 緊急介入、yellow 4 週間 → escalation。

## リスクと対策

| リスク | 確率 | 対策 |
|-------|------|------|
| 大手の決裁スピードが遅い | 高 | 中堅 5 社で実績作って大手へ |
| 価格交渉で値引きしすぎ | 中 | 「初年度は据え置き、次年度から ARR 5%up」を標準化 |
| 競合（Palantir 日本）参入 | 低-中 | 業界深掘り + 日本サポートで差別化死守 |
| パートナー SI が顧客を抱え込む | 中 | 直販ルートを必ず維持、SI は augment の位置づけ |
| 採用市場で人取れない | 高 | エンジニア基準は「技術 + 業界経験」、後者で hire 母集団広げる |

## 注意

- **製品が走らないと営業は走らない**: 50 点未満で大手営業すると「机上の空論」と一蹴される
- **CS は事業の核**: 売って終わりの SaaS と違い、Foundry 型は **顧客の現場で価値を作る** モデル。CSM の質が再契約率を決める
- **業界での評判は 10 年効く**: 1 件の悪い噂は 10 件の good case を打ち消す。**初期顧客選定は超慎重に**
- **海外展開は早くて T+24M**: 日本でデファクト確立してから東南アジア（香港・シンガポール・タイ・ベトナム）。中国は別モデル
