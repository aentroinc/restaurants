- **PoC は固定価格・固定スコープ**（リスクを当社側が引き受ける）

- **API追加は1本あたり標準価格を提示**（顧客が後から追加判断できる）

### 1.2 工数算出ロジック

各APIの実装工数 = 「**標準工数**（テンプレからの定型実装）」 + 「**カスタム工数**（顧客固有の業務マッピング）」

- 標準工数: 認証実装・基本的なデータ取得・コントラクト定義・基本UI表示
- カスタム工数: 顧客の業態固有のフィールド・業務ロジック・既存システムとの差異吸収

### 1.3 PoC vs 本格導入の違い

| 観点 | PoC | 本格導入 |
|---|---|---|
| 目的 | 価値検証・経営判断材料化 | 全店舗での業務代替 |
| データ | サンプル/部分接続も可 | フル連携、過去データマイグレーション含む |
| UI | 主要画面のみ、デザイン簡易 | 全業務アプリ、カスタムブランディング |
| 運用 | 当社エンジニアが手動補助 | 顧客運用 + SLA保証 + オンコール |
| セキュリティ | 最低限（基本認証/簡易権限） | SSO/MFA/監査ログ/列ACL/PII管理フル |
| SLA | ベストエフォート | 99.5%稼働、4営業時間応答 |

## 8. 経営判断ポイント

### 8.1 価格設定の戦略的意図

1. **PoC は価値検証フェーズ → 当社のリスクを大きく取る**
   - 顧客は「失敗しても300-1,800万円」で判断できる
   - 当社は「PoCを成功させれば本格導入の確度80%」と見込む

2. **本格導入は店舗数の階段制ではなく「機能パッケージ + 店舗数調整」**
   - Foundry的な「年契約フィー」モデル
   - 顧客が店舗を増やしても料金が線形に上がらない（ロックイン要素）

3. **Enterprise は1社で年商10億円以上の大型案件**
   - 営業コストが高くても回収可能
   - 1社受注で会社のレファレンス価値が大きく上がる

### 8.2 リソース計画

**現状リソースで対応可能なPoC同時並行数**:
- PoC Lite: 4-5社まで
- PoC Standard: 2-3社まで
- PoC Enterprise: 1社（リソース集中）

**本格導入を年5社受注するために必要な追加採用**:
- バックエンドエンジニア +3名
- フロントエンドエンジニア +2名
- カスタマーサクセス +2名
- BizDev +1名

### 8.3 値引き戦略の上限

| パッケージ | 通常価格 | 値引き上限 | 理由 |
|---|---|---|---|
| PoC Lite | 300万円 | -10%（270万円） | 営業コスト下限 |
| PoC Standard | 800万円 | -15%（680万円） | 戦略顧客 |
| PoC Enterprise | 1,800万円 | -20%（1,440万円） | レファレンス価値 |
| 本格導入 Standard | 4,500万円 | -15% | 複数年契約条件 |
| 本格導入 Enterprise | 1.2億円〜 | -20% | 業界レファレンス・複数年 |

### 8.4 注意点・リスク
- **NDA系APIの工数は実態が読みにくい**: 大手POSベンダーとの個別仕様調整は想定の1.5-2倍に膨らむことがある。Enterprise案件では初期見積もりに20%のバッファを織り込むこと。
- **PoCから本格導入への転換率**: 業界標準の60-80%を目標。PoC失敗時の出口戦略（最低限の価値提供 + 学習結果の納品）も契約に明記。
- **競合の急速な追従**: スマレジ・freee等が「分析機能」を強化してきた場合、当社の優位性は「オントロジー × 業務オペの統合」に集約される。価値訴求のフォーカスを常に確認。
